# Signal Types

本文档定义 `cw-xlsx-to-wiki` 分析模式建议支持的 `signal` 类型。

`signal` 是客观信号，不是最终洞察。
它只回答“看到了什么”，不直接回答“这意味着什么”。

## 第一版优先类型

### 1. `completeness_gap`

用于识别：

- 关键字段缺失率过高
- 空值集中在特定区域
- 关键列存在大面积空字符串或无效占位值

典型可升级问题：

- 关键字段缺失是否已经影响业务流程或分析可信度？

### 2. `distribution_outlier`

用于识别：

- 极值
- 离群点
- 分布断层
- 异常波动

典型可升级问题：

- 这些异常值代表真实业务波动，还是数据录入 / 口径问题？

### 3. `concentration`

用于识别：

- 贡献度过度集中
- 头部对象异常突出
- 单一区域 / 单一客户 / 单一品类依赖过高

典型可升级问题：

- 当前增长是否过度依赖少数对象，导致韧性不足？

### 4. `consistency_gap`

用于识别：

- 汇总与明细不一致
- 跨表冲突
- 应相等字段不相等

典型可升级问题：

- 当前数据是否存在统计口径不一致或流程断点？

## 第二阶段可扩展类型

### 5. `trend_shift`

用于识别：

- 时间趋势反转
- 周期性变化异常
- 某指标短期异常上涨或下降

典型可升级问题：

- 当前变化是短期噪声，还是结构性拐点？

### 6. `schema_risk`

用于识别：

- 列类型混杂
- 疑似脏字段
- 表头语义不清

典型可升级问题：

- 哪些字段质量风险会影响后续管理判断？

## 问题排序建议

候选问题建议至少按下面四个维度打分：

1. `impact`
2. `explainability`
3. `evidence_strength`
4. `actionability`

默认只保留前 `3-5` 个问题进入正式报告。
