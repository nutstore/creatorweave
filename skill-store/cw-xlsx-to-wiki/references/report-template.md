# Report Template

本文档定义 `cw-xlsx-to-wiki` 分析模式当前建议的报告结构。

这份报告的重点不是“列出所有统计结果”，而是把最值得负责人关注的问题讲清楚。

## 固定结构

建议按下面顺序组织：

1. 管理摘要
2. 当前最值得关注的问题
3. 每个问题的可能原因
4. 建议进一步验证的事项
5. 建议后续关注的指标或动作
6. 证据附录
7. 局限与风险

## 洞察块结构

每个问题块建议固定包含：

1. 现象 / 信号
2. 为什么值得关注
3. 可能原因
4. 还缺什么信息
5. 建议下一步动作

## 渲染原则

- 优先保证可读性和稳定性，不先追求复杂视觉效果
- 第一版可以只用少量内联 CSS
- 不默认引入前端图表库
- 如果需要写出 HTML，采用流式写入，避免一次性在内存中拼接完整文档
- 报告的主角是高价值问题，不是所有信号的平铺罗列

## 摘要原则

- 摘要应只基于已排序的问题和已确认的 `signals`
- 不要在摘要中引入无法回溯到证据对象的新结论
- 对不确定性较高的原因假设，应明确标记为“待验证”
