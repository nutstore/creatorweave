# Report Audience

本文档定义 agent 在组织洞察报告时应如何考虑受众。

同样一份数据，不同受众看到的重点不同。
如果不先判断“写给谁看”，报告很容易变成平铺统计。

## 一、老板 / 负责人最关心什么

通常最关心：

- 哪些问题值得优先投入注意力
- 这些问题会影响什么判断
- 背后可能是什么原因
- 下一步需要什么动作

通常不关心：

- 所有字段的完整统计
- 大量底层计算细节
- 没有管理含义的异常罗列

## 二、面向老板的报告应突出什么

### 1. 优先级

先说最值得关注的 `3-5` 个问题，不要平铺所有信号。

### 2. 含义

每个问题都要说明：

- 为什么值得关心
- 它可能影响什么

### 3. 不确定性

如果原因只是猜测，要明确标记“待验证”。

### 4. 动作

老板看到报告后，应该知道：

- 要不要继续查
- 查什么
- 谁该负责

## 三、不同受众的表达差异

### 1. 老板 / 业务负责人

重点：

- 风险
- 机会
- 优先级
- 动作

### 2. 中层分析或运营团队

重点：

- 问题拆解
- 细分原因
- 验证路径
- 数据补充需求

### 3. 数据或技术团队

重点：

- 口径
- 数据质量
- 同步链路
- 系统约束

## 四、写作淘汰规则

以下内容不应成为报告主角：

- 只是证明“做了很多统计”
- 没有动作价值的图表描述
- 不区分受众的统一话术

## 五、推荐结构

面向老板的简版结构建议是：

1. 管理摘要
2. 当前最值得关注的问题
3. 每个问题的可能原因
4. 建议验证事项
5. 建议后续动作

证据附录可以放后面，但不应抢主叙事。
